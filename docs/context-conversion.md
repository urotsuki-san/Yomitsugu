# 文脈とタイポ補正の改良

同じ読みでも、前後の文章によって適切な漢字は変わる。「この紙を」に続く「きる」と、「新しい服を」に続く「きる」を区別するため、確定済みの前後文脈を変換モデルへ渡すようにした。

## 変更した処理

辞書にある「辛い」の読み「カラ」が、入力していない「い」まで補う原因になっていた。漢字を含む見出しの送り仮名を読みと照合し、対応しない項目を変換の探索から除く。ユーザー辞書の読みは、この検査で変更しない。

候補には、入力された読み全体を変換したものを優先する。短い入力で助詞のつながりや語尾の解釈が曖昧な場合は、統計的な変換器で候補を増やし、ローカルモデルで順位を再評価する。この再評価はSpace・Enterの処理で行う。打鍵中は既存のタイポ候補を保ちながら、軽い変換を続ける。

学習では、手で選び直した候補を自動確定の回数より優先する。前後8文字から作った照合値を使い、異なる文脈の選択が互いを上書きしないようにした。保存するのは読み・選択した候補・回数・時刻・照合値で、周囲の文章そのものは保存しない。

## タイポを退行させない試験

[85例の固定入力](../native/tests/conversion_cases.tsv)には、タイポ・非標準綴り23例が含まれる。[0.2.9で測った順位](../native/tests/conversion_baseline.json)を比較元として保存した。以前は第一候補だった入力が第一候補から外れた場合、または5候補以内だった入力が圏外になった場合、CIを失敗させる。総数だけを比較して、別の入力の改善で退行を埋め合わせることはしない。

[文脈付きの37例](../tests/context_conversion.json)では、「空」「辛い」、熱さ・厚さ、紙・髪・服などの同音異義語と、インストール／アンインストールの入力を確認する。「中が空」は第一候補、「空の容器」は3候補以内を要求する。文脈を替えた後のキャッシュと、打鍵中・確定時のキャッシュが混ざらないことも検査する。

## 参考にした公開資料

- [ATOKのパーソナライズドコレクト](https://atok.com/features/column/vol_3.html)は、同じ誤入力でも前後の文章や過去の入力傾向から補正を選び分けると説明している。Yomitsuguでは、文脈の利用と明示的な選び直しの保存を改善の対象にした。ATOKのコード・辞書・内部アルゴリズムを取り込んだものではない。
- [Zenzaiの仕様](https://github.com/azooKey/AzooKeyKanaKanjiConverter/blob/main/Docs/zenzai.md)には、前後文脈と推論回数による精度・速度の調整がある。既存モデルの文脈入力を接続し、再評価する候補数と入力の長さに上限を設けた。
- [ニューラルかな漢字変換システム Zenzai](https://www.anlp.jp/proceedings/annual_meeting/2025/pdf_dir/P1-19.pdf)は、統計的な候補探索とニューラルモデルを組み合わせる研究。既存のAzooKey/Zenzaiを使い、候補の探索幅を調整する際に参照した。
- [AJIMEE-Bench](https://github.com/azooKey/AJIMEE-Bench)の200例を、報告された入力とは別の評価に使った。リビジョンは`401666cd56d1a570c2021798b64b6da4396bfd45`。かなの読みを本製品のローマ字表で入力へ戻し、候補の全文一致を数える。文脈付き100例と文脈なし100例があり、データはCC BY-SA 3.0。製品の辞書や学習データには加えていない。

ATOKやGoogle日本語入力との同一条件の比較は行っていない。この試験だけで、それらと同等の精度とは判断できない。
