# Preview 3 の変換精度と待ち時間

「原因」「店員」などを含む8入力では、正しい表記を早く表示できるようになった。一方、別に選んだ16入力では、開発中の直前の版より表示が落ち着くのが遅かった。

## 「原因」「店員」など8入力

同じ8入力を各版で3回ずつ打ち、最後のキーを押したときの入力処理が返ってから、入力欄の文字が最後に変わるまでを測った。「正解」は2秒後の表示とEnterで確定した表記がともに指定の表記と一致した回数。8入力のうち2件は、初回と繰り返しで差が出るかを見るため同じ `geninn` を使った。

| 版 | 第一候補で正解 | 表示の中央値 | 表示のP95 | 全候補がそろうまでのP95 |
|---|---:|---:|---:|---:|
| 前の公開版（Preview 2） | 9/24回 | 92 ms | 388 ms | 548 ms |
| 中間の開発版（.13） | 24/24回 | 262 ms | 548 ms | 563 ms |
| Preview 3 の変換エンジン（.14） | 24/24回 | 23 ms | 218 ms | 610 ms |

P95は測った値を短い順に並べたときの95%地点。表示が早く決まっても、裏でほかの候補を探す処理は続く。たとえば「原因を調べる」の表示が落ち着くまでの中央値は、中間の開発版で548 ms、今回は27 msだった。版を測る順番を入れ替えた追試でも、8入力全体の中央値は262 msから53 msに短くなった。

## 追加の16入力

単語、短文、同音語、撥音の打ち落としを各4件選んだ。両版とも各回11件が正解で、残る5件で確定した表記も両版で同じだった。たとえば「かいせん」は基準を「回線」としたが、どちらも「海鮮」になった。

| 指標 | 中間の開発版（.13） | 今回（.14） |
|---|---:|---:|
| 第一候補で正解 | 33/48回 | 33/48回 |
| 表示の中央値 | 77 ms | 105 ms |
| 表示のP95 | 374 ms | 387 ms |
| 全候補がそろうまでのP95 | 497 ms | 454 ms |
| 1打鍵の処理時間のP95 | 0.83 ms | 0.72 ms |
| 変換プロセスの専用メモリのピーク（先の8入力を含む） | 65.67 MiB | 65.59 MiB |

## 測定条件

Windowsの試験用入力欄に40 ms間隔でキーを送り、最後の打鍵後に2秒間観測した。既定の「自動最適化」、学習なし、各回は空のプロファイルから開始。変換処理は論理CPU 1個に割り当てた。時間は入力欄の文字が更新された時刻で、Chromeの画面に描画された時刻とは異なる。メモリは変換プロセス単体の値。

この時間を測ったのは公開直前の .14。公開版ではその後、`kanin` のように末尾の n の取り方が複数あり、前後の文からも別の読みの表記を絞りきれない場合に、ひらがなを先頭に残すよう修正した。別の210種類の入力では、.13と.14で確定時の候補（最大16件）と順位がすべて一致した。
